# 手机照片上传排查与验证

## 已确认的问题

原选图逻辑仅允许 MIME 为 image/jpeg、image/png、image/webp 的文件，单张限制 5MB。它会拒绝大于 5MB 的相册照片、HEIC，以及没有 MIME 信息的部分有效 JPG。失败后立即清空 file input，报错却位于较长表单底部，容易造成选图后没有反应的体验。

线上云存储权限已只读核对，为所有用户可读、仅创建者及管理员可写。当前未发现明显的权限配置错误，但这不能代替真实手机用户的上传验证。尚未取得反馈者的手机型号、浏览器、照片格式和具体错误，不能认定此次反馈只有格式或大小这一个原因。

## 本次修复

- 保留最多 3 张，源文件上限调整为单张 20MB；普通照片超过 5MB 时在本机压缩到 5MB 以内。相册文件本身不改动。
- MIME 缺失时依据扩展名进行初筛；提交时再检查实际文件头并解码，防止仅更换扩展名的文件混入。
- HEIC/HEIF 在浏览器能够解码时转为 JPG 上传。不支持时给出导出 JPG 或选择截图的明确提示，不承诺所有手机都能转换。
- 所有照片按顺序检查、处理完成后才开始上传，避免第二张格式出错时第一张已被上传。
- 在选图控件旁显示状态；保留已选文件与文字。提交期间禁用重选与关闭，阻止重复提交。
- 小于等于 5MB 的 JPG、PNG、WebP 验证通过后保留原始字节；转换后的照片最长边不超过 2048 像素。此上限用于控制手机画布内存，需要更高分辨率时应另做服务端处理。

## 已做的检查

运行 `node tests/contribution-images.test.cjs`，覆盖数量和大小边界、无 MIME 图片、伪造扩展名、HEIC 转换、压缩、解码失败、资源释放、失败不清空选图，以及提交前先完成全部照片校验。通过 `node --check script.js`、`node --check contribution-images.js` 和 `git diff --check`。

自检中的图片解码和画布采用模拟实现，用于检查分支、尺寸控制和错误处理；不等于真实手机编解码测试，也没有创建云端测试投稿。浏览器连接不可用，手机完整上传尚未实测。

## 上线后复核

1. 安卓手机和 iPhone 各用实际使用的浏览器或微信页面测试一张普通 JPG。
2. 选择 6—10MB 的照片，确认自动处理后能够提交。
3. 选择 HEIC，确认支持时转换成功，不支持时就地显示更换格式提示。
4. 选择 4 张或超过 20MB 的照片，确认就地提示，已填文字仍在。
5. 断网后点击提交，确认报错且保留内容，恢复网络后重试。

截至本次排查，GitHub 推送因现有凭据失效而未成功。需发布本次完整文件集后再复核，不能将本地通过视为线上已修复。
